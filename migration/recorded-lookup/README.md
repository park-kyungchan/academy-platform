## Actual retained behavior

`loadSavedContext` reads only `tools/academy-mcp/architecture/source-pins.json`, `private/student-audit-20261014/audit.json` and `private/lesson-20261014/overlay.json` under its supplied root. It checks required pins, SHA-256, regular non-symlink leaf files and the 32 MiB leaf size bound, then the original audit/lesson parsers. Audit parsing requires exactly five students and distinct nonempty opaque student IDs. Lesson students must belong to that audit. These checks are not account authorization, ownership/mode validation or validation of symlink ancestors. The source pin manifest is not independently authenticated by the loader; this driver independently pins the supplied corpus instead.

The source input schema is a strict object: `sourceMode` defaults to `saved_context`; `limit` defaults to 10 and is an integer 1–250; optional `cursor` has at most 2048 characters. Strict query variants are `roster`, `student_summary(studentId)`, `student_records(studentId, facet, bookEditionId?)`, `student_history(studentId, facets?)`, and `lesson_context(studentId, date)`. Student and edition IDs are nonempty strings of at most 256 characters; lesson date is a valid ISO date. Facets are exactly books, sections, attempts, assignments, videos, daily_tests, daily_records, teacher_events, daily_record_drafts. History facets are nonempty, unique and bounded by that list. These schema details describe the source; this finite S05 corpus does not exhaust every admitted input or budget branch, and does not exercise the history batching variant.

In the selected contract:

- Roster membership uses exact preserved `studentId`, not display name or native key. No trim/coercion/name guessing occurs. Unknown IDs return `unavailable/student_not_in_preserved_roster`; duplicate audit IDs throw `student_scope_invalid`. Duplicate display names are retained and distinguished by ID. This source boundary has no name-to-native-ID resolution and does not promise duplicate-name refusal. The separate resolver's synthetic tests were inspected as leads, not executed or absorbed into this contract.
- Edition filtering is admitted only for books/sections and only for a listed student edition. Unsupported facet filters and guessed editions return their exact unavailable codes. Original source row indices survive filtering.
- All successful selections remain `partial`, including exhausted pages. Unknown selections remain bounded evidence, never a complete teacher roster. Empty selected evidence returns `partial`, zero records, an exhausted page and the exact additional unknown statement. An unavailable selection instead has a null total, zero returned, `exhausted:false`, null cursor and a refusal code.
- Source records preserve missing score, explicit null, blank string, numeric zero, `unknown` and explicit `not_performed` as different values/presence states. Dated teacher reports, supplied context, server observation snapshots and unsaved drafts keep their separate classifications. They are not reconciled into a completion flag. At the collection level, the reference intentionally maps missing or null video arrays to the same empty selection; the corpus preserves the underlying distinction in the pinned audit, and the contract does not falsely claim the query distinguishes them. Summary `recordedHistoryCoverageClaim` also uses the source's null fallback.
- Sections and attempts stay in input order. Book-filtered source pointers retain original indices; `~` and `/` are escaped as `~0` and `~1`. Object-valued daily-test evidence follows original entry order. The snapshot hash uses the two exact file hashes. A cursor uses base64url of ordinary JSON containing version, snapshot, SHA-256(JSON.stringify(parsed query)), and next offset. It is bound to selection/snapshot, not authority; malformed/cross-selection cursors return `cursor_scope_or_snapshot_conflict`.
- Query schema failures throw the original `ZodError` including full message and issues; semantic `QueryRefusal` during selection becomes the full unavailable envelope. Loader/pin/parser failures remain throws. The adapter serializes an original thrown Error's name/message and optional issues; catching one into this frame is not a successful query. Child process status remains a separate comparator input.

The reference does not expose a source account namespace or authenticated account key. Its fixed teacher label and preserved roster claims must retain their exact meaning; they must not be treated as proof of live entitlement. A future account-qualified object ID or cross-account traversal is new design, not behavior already proven by these saved bytes.

## Adapter, isolation and judge

`baseline.ts --source-root ABSOLUTE_CHECKOUT --evidence-root ABSOLUTE_TEMP_ROOT` reads one JSON request on stdin and invokes the actual pinned source by dynamic import. It never reads the oracle. Each reference check launches a fresh Bun child from a disposable cwd with an allowlisted environment (no inherited credentials), no auto-install and an empty temporary HOME. The adapter supplies a fixed test clock, `2026-11-02T00:00:00.000Z`, solely to make `retrievedAt` deterministic; source observation dates and all other values are unchanged. This is a test clock, not a capture timestamp. No values are normalized away after execution.

`deny-transport.ts` loads before the source import and denies fetch/http/https/net/tls JS connection paths while counting denied attempts. The selected source import closure contains no transport and no lock/journal code. Explicit guard-only GET `DayRecordServlet?reqCmd=udtPrg` and POST probes are denied with one counted attempt each and no dispatch. The known mutating GET identity is supported by `lessonJournalHttp.ts` and `AcademyHttpClient.applyJournalAction`; method GET is never an allowance. A query carrying that operation is also rejected by the actual strict saved-query schema. These guard probes do not execute AcademyHttpClient or establish its broader live HTTP authorization. No production credential, source request, real lock/journal, print, save or parent-send path is used.

The local fake is only a counted function, with no network endpoint. Five actual-child negative controls produce status 7, stdout junk, stderr junk, a forbidden fake dispatch and a denied network attempt. Thirteen additional value mutations exercise wrong book/provenance/digest/cursor/refusal, missing required fields, changed unknown/completion states, null-to-missing, blank/unknown-to-zero and array reorder. The comparator rejects all 18. It requires child status 0, no signal/spawn error, empty stderr, exactly one canonical compact JSON line on stdout and exact expected logical values. It preserves the real child status, stdout and stderr separately. It neither trusts an outer wrapper's success nor sorts arrays/drops unknown fields.

This is instrumentation of a trusted, pinned local TypeScript reference, not an OS network sandbox or proof against an adversarial candidate spoofing effect counters. Future Rust/fake-target work must independently observe its own effects and preserve these expectations; self-reported zero dispatches are insufficient for a new transport implementation.
