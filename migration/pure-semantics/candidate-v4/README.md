## Boundaries and interfaces

The original `width`, `week`, `month`, and `semantic_v3` protocols remain available. The legacy semantic_v3 admission domain remains historical compatibility: its old depth/offset admission refusals are not source refusals. New `semantic_v4` accepts a flat UTF-16/binary64 graph and explicit clock/UUID test ports, and emits complete outcome/events/effects/metadata frames. The candidate reads stdin only and never reads corpus/expected files or starts Node/Bun. Test constructors in `driver.mjs` lower named descriptors and build fixed synthetic HTML. `compare.mjs` separately reads qualified expectations and invokes the unchanged qualified judge.

Learning keeps its own depth64 guard. Admission and CISM encoders, graph decoding, cloning and dropping use explicit work stacks. Transport admission is a 16MiB envelope/65,536 expanded nodes; legacy requests retain 1MiB. These are transport budgets, not source limits. Native APIs do not impose a new64/96/512 nonlearning limit. Source-return parity is qualified through1000; a separate10,000-depth native test proves representation safety only, not uncharacterized source-engine behavior.

The clock's raw finite epoch-ms value is used before intake/hash without string TimeClip or rounding; the test UUID is injected before handle and digest creation. Learning and DailyRecord instant grammars, native epoch-ms/truncation, the three JSON/digest families, general ordered schema diagnostics/defaults/refinements, CISM source membership/URLSearchParams encoding and admission's distinct tuple/admission/action hashes are separate implementations.

`learning::{known_frozen,unknown_frozen,context_from_lesson_key,resolve_problem_path}` and `frozen::FrozenValue` provide immutable detached native returns with no mutable references. `learning::call` and mutable `knowledge` helpers are comparison/data construction interfaces, not a claim that a Rust `Js` object is a frozen JS object. `FrozenValue::copy` validates learning JSON, and its private value has no mutable accessor. Tests mutate original inputs/detached copies, compare distinct child pointers, and exercise write refusal. JS `Object.isFrozen`, prototype descriptors and engine TypeError observers continue using the unchanged original TypeScript compatibility port; Rust has no JS heap or interpreter.

`admission::Admission` takes an `Rc<RefCell<Js>>` shared launch view. Initial tuple keys and admission digest are captured once; later current-request comparisons read the same launch view. `admission::OwnerRecord` has private immutable outer fields and preserves the owner's mutable request reference. Tests verify both identities, changed launch comparisons, tuple capture, callback error ordering and local-used behavior. The existing `native-dailyrecord-backend.ts:581` owner and `liveSaveRequestEvidence` real-file reader remain unchanged. Their durable consumeOnce/file custody/locks/effect authorization belong to S10.

Actual observing callers retain their original ports: `learning/{identityMapping,reconciliation,revisions,weekly}.ts` still call original immutableCopy/known; `academyHttpClient.ts:11` still imports original learning canonical/digest/date/key checks; `native-dailyrecord-backend.ts:581` still constructs the original admission with its real evidence reader and durable owner. No production caller is switched. `source-exports.json` is a static inventory of those original compatibility module exports, derived from declarations in the six selected source files, not a claim that the out-of-scope DailyRecord save/metadata methods were ported to Rust.

`evidence::parse_bytes` is the pure decoding half of the retained file reader. The comparison driver supplies disposable byte steps and their missing/oversize state; the Rust candidate does not open any real path. Pinned Bun JSON syntax diagnostics cover the selected malformed prefix/BOM fixtures; arbitrary JavaScript JSON parser diagnostics are uncharacterized. This is not a replacement real-file owner. Arbitrary proxies/getters/toJSON/host objects and full DOM/runtime space remain uncharacterized. Named descriptors construct fixed test data only.

The inert parser uses `scraper`'s real HTML5 DOM and selectors, never evaluates script, and applies the retained source-function selector and CISM validations. All18 selected original parser cases are included; S09 still owns production transport/recorded breadth. General Intl engine equivalence is not claimed; the default native zone-name check uses pinned IANA names plus source offset syntax, with original Intl consumers unchanged.
