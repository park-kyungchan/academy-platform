# Measurement harness (slice 1 repair)
`python3 run.py Q01|Q02|Q03 <model> --mode isolated|installed` runs exactly one session.
Both modes use a per-run strict MCP config, an empty working directory, stream-json with verbose output and --include-hook-events, and no session persistence.
`isolated` uses `--setting-sources "" --tools "" --disable-slash-commands --system-prompt "You are an assistant of a teacher. Use the tools you are given."`; existing CLI login is retained without reading or passing credentials.
`isolated` measures the server's own texts alone, with the fixed neutral system prompt and user setting sources disabled.
`installed` measures the same with the user's instructions, skills and hooks loaded, without file or shell tools.
Each temporary run directory holds mcp.json, run-log.jsonl, claude.jsonl, claude.stderr, answer.txt and measurement.json.
Tool names/inputs, the last Academy result matched by tool_use_id, answer, usage and cost come only from the stream; argument bytes use compact UTF-8 JSON. Other tools never supply the display reference.
M24 carrier: every server tool result has the exact `tools::DISPLAY_DIRECTIVE` text block followed by the teacher display. The reference and delivery byte count use the display alone; the answer is never stripped, so a repeated directive is an M21 added line. Native newline-flattened carriers are recognized only by that exact leading line; legacy display-only captures remain readable. No fidelity policy or matcher rule changes.
`received_form` is envelope when received JSON has a string display (that field is the reference), otherwise display_text; no Academy result is unknown. `shown_unchanged` compares whitespace-normalised reference text; `extra_chars` counts normalised answer characters outside its first complete display occurrence (all answer characters if none). Missing evidence or an empty/whitespace-only reference is `unknown`.
Answer date/forbidden-date/order/line checks use checks.json; failed measurements never justify changing the server, list or displays.
Offline tests: `python3 -I -m unittest discover -s crates/edu-academy-teacher/harness`; overrides: EDU_ACADEMY_TEACHER_BINARY and CLAUDE_BIN.
The exact command and fixed system prompt are saved in measurement.json; no authentication environment is changed.
Isolation checks init fields tools, slash_commands, terminal_slash_commands, skills, plugins, agents and mcp_servers when present; missing tools/init/first-request usage fails closed.
Only the 14 configured Academy tools and CLI agents claude, Explore, general-purpose, Plan, statusline-setup, web-fetch are allowed. Every listed plugin must have path=builtin.
Non-builtin plugins, skills, slash commands or hook stream events fail isolation; all existing inspected init fields and values are recorded. Native memory_paths metadata is also recorded, but an auto-memory destination does not prove a file load. In isolated mode the first assistant message's input+cache-read+cache-creation must be under 6,000 tokens; exit 3 signals that isolated bound. Installed mode reports first_request_tokens and continues because user instructions are intentionally loaded.
Installed adds exactly `--tools Skill` alongside the per-run Academy allow list; it retains user settings, instructions, skills and hooks. No configuration file is edited.
Both modes request --include-hook-events; isolation records hook_condition as pass/FAIL only with that flag. Older streams give hook_condition=unknown and pass (hooks unknown) if the other isolation checks pass.
Offline re-scoring: python3 -B crates/edu-academy-teacher/harness/rescore.py <run-dir> [...]. It uses the same score_stream as live runs, reads evidence without modifying it, and emits only mode/request/model/received_form/shown_unchanged/facts_kept/source_footer/closing_statement/failed_rules/extra_chars/isolation/delivery. No tool arguments, file contents, answers or reference text leave the saved directories.
Installed rows retain a reduced fail-closed check: exactly one init, well-formed stream, and a tools list limited to per-run Academy names plus Skill. Passing this check reports `not_applicable`; failure reports `FAIL` with reasons. Full isolation criteria apply to isolated rows. Hook evidence remains recorded.

Q03 requests preparation for the unknown class 가상반Z on scenario v2, triggering a class_name ask with the three known class labels. Checks require every label and exactly one Academy call before a teacher answer; Skill calls are counted separately in total calls.
`received_text_bytes` is the UTF-8 length of the last delivered Academy text before whitespace normalisation. Per-call lengths are matched by tool-use id in the stream, then by tool name and call order to the optional server run-log. `delivery` is `same` when all matched lengths equal display_bytes, `truncated_or_changed` on a mismatch, or `unknown` if evidence cannot be paired. Equal byte lengths do not prove equal content; shown_unchanged scoring still uses the delivered text.

Q01/Q02 previous_lesson_date: the assignment/record provenance names November 9; forbidden-date checks reject November 4 (ISO and Korean forms).
Q01 line0 and Q02 line1: A's 2-1 video row says uploaded and awaiting teacher confirmation, without server/teacher completion claims.
Q02 roster_order: complete student action blocks occur in roster order A, B, C (reminders stay in their separate section).
Q02 line0: B's video absence is scoped to the lists, never a claim the student did not do or upload the work.
Q03 labels and academy_calls_before_answer: show all three class choices and wait after one Academy call. The default fixture is scenario-v2.json.

`shown_unchanged` reports complete whitespace-normalised delivered-text inclusion; missing/malformed evidence is unknown (stored legacy alias: `verbatim`).
`facts_kept` uses M21 reference units only: title, part/student heading, table header, complete bound row, complete statement, optional footer and closing; every nonempty reference line must be assigned.
Only reference headings change answer context; matching consumes one answer logical line per required unit with multiplicity, and rows may reorder within their original binding.
Complete-assignment search tries every compatible cell-break grouping (including shared prefixes/duplicates); surrounding whitespace, ASCII/full-width delimiters and a single outer fence are presentation; other value edits remain significant.
Every unmatched answer line counts as added: any addition under a required part fails; outside those parts only one stateless non-row line is allowed and never changes context.
`source_footer`/`closing_statement` separately count optional unit retention; whole table-separator lines are explicitly normalized away on both sides and can satisfy no unit; unsupported reference structure or missing evidence gives unknown; declared resource limits also return unknown with a reason, never FAIL; unknown never accepts a slice.
`checks.json` declares grammar, normalization, provenance, state words and limits (4096 reference units, 65536 answer UTF-8 bytes, 10000 entered states per search); iterative search prunes suffix deficits and stops with reference_too_large/answer_too_large/search_budget; accept a slice on `facts_kept`, reporting `shown_unchanged` beside it.
Offline: `python3 -I -B -m unittest discover -s crates/edu-academy-teacher/harness`; `python3 -B crates/edu-academy-teacher/harness/rescore.py <run-dir>` exports counts/categories and failed M21 numbers only; run summaries and rescore unknown_by_reason count unknown results per reason (rescore totals on stderr); unit_counts includes optional units.

Slice 2: `python3 -B run.py Q11|Q12|Q13|Q14|Q15|Q16 haiku|sonnet --mode isolated|installed` selects scenario-v3.json unless --scenario is explicit.
Each entry has literal teacher `turns[]`, expected_tool, one-call bound, fixture, clock expectation, independent line/forbidden checks and the unchanged strict M21 policy.
The installed client's --help supports --input-format stream-json with --print. The driver starts one client and one synthetic MCP server, sends `{"type":"user","message":{"role":"user","content":"..."}}` on stdin, and sends the next user message only after the prior result event. Stdin stays open between turns, so earlier messages and tool results stay in that conversation; no resume, fresh prompt or second server substitutes for a second turn.
Q12 re-asks the same request; Q14 supplies only the exact selected edition. The second call must preserve previous arguments (Q14 may add/change book). --trial marks a disposable contract trial through the explicit trial field on each numeric/category row. The Q14 trial on this host completed two turns under one session id, with prior arguments retained. Every exported row now carries trial=true only when --trial is selected; modes remain isolated or installed.
The driver never re-sends or retries a failed turn. A client error, EOF or timeout stops submission in both modes. First-request input+cache-read+cache-creation >=6000 stops submission and returns exit 3 only in isolated mode. A later missing turn scores unknown, never the prior answer.
Per-turn result boundaries separate calls, argument bytes, usage and duration_ms (reported in seconds), while the first init is retained for isolation evidence. Raw fixture equality and clock checks are distinct from shown_unchanged and M21 facts_kept. Q15's broader bare-unit result fails the narrow fixture/forbidden-activity checks even if it honestly preserves the broader delivered facts.
Slice 2 stdout exports only request/turn/tier/mode, call and argument counts, reference/kept/missing/added counts, result categories, reason codes, failed M21 rule numbers, four numeric token fields and client duration. Evidence, answers, references, arguments, session ids and private paths stay in the harness-created mode-0700 directory. measurement.json retains full per-turn results for audit; no private path is printed. rescore.py remains the slice 1 offline exporter; it does not accept slice 2 requests. For the saved disposable trial, --replay-trial --trial re-scores the unique matching harness evidence without a client launch; --jsonl <path> appends harness-produced rows (0600), with no placeholders for runs that were not made. A non-unique saved trial fails closed. Measurement metadata records request/model/mode/trial, sent-turn count and the driver reason.
Offline driver tests use a fictional child process to verify ordering, per-turn scoring, missing-turn unknown, preserved arguments and no retries; no model is launched by tests. `python3 -B -m unittest discover -s crates/edu-academy-teacher/harness` is the complete check, with a 20-second idle-host limit.

The property generator now moves complete logical rows; a regression pins both the allowed complete-block rotation and the rejected detached-qualifier rotation. fidelity.py and all declared M21 limits remain unchanged. The existing required rust job also runs the complete offline suite.
The public result fails on isolation or changed delivery, and remains unknown on missing checks/delivery, independently of facts_kept. Isolation evidence covers the whole conversation; its token bound uses the original first assistant request, rather than the larger second-turn context. Q11's order check matches table-row starts so edition-name substrings cannot affect it. The native stream client emits init again on the next teacher turn. Isolation accepts those repeats only with a nonempty identical session id, one init per turn, and identical tools/extensions/memory/server snapshots; any changed snapshot or session still fails. The first assistant request supplies the token budget once for the entire conversation. Saved non-trial measurements cannot be relabelled by --replay-trial; legacy trial evidence without a trial field requires the explicit --trial option and a unique matching evidence directory.


Counts-only difference classes: `python3 -B diffclass.py <saved-run-dir> [...]` reads evidence as rescore.py does, or `--rows <harness-rows.jsonl>` resolves each row to exactly one saved run by mode/request/tier, conversation, trial and the saved numeric fingerprint (calls, argument bytes, unit counts, fidelity, duration and four usage fields). `--output <new-file>` writes the same rows as stdout, mode 0600, without overwriting. No answer/reference/argument, label, matched text, input path or exception payload is exported. Missing/non-unique evidence is unknown with a fixed reason code. Old trial metadata is matched by its numeric fingerprint; normal saved runs cannot match a trial row.
The classifier is diagnostic only: fidelity.py, its tests, policies and acceptance outcomes remain unchanged. For non-kept pairs it uses the existing M21 diagnostic path to inventory every missing reference unit and every added logical line, with multiplicity, optional units included; a kept pair emits zero line classes. Every turn still reports byte/physical-line lengths and three independent literal comparisons. A result/ask/stop kind comes from the paired server log. Ask choices come from the visible `- label: meaning` lines (ambiguous option separators give ask_labels_unavailable); non-asks have an empty choice set and choices_present=true.
Similarity is multiset Dice: 2*sum(min(count_ref,count_line))/(ref_tokens+line_tokens), on NFC/casefolded Unicode word tokens after marker stripping. The highest-overlap answer line is closest, with first physical line winning a tie. Classification priority there is equal_after_marker_strip, then equal_after_spacing_punctuation. Marker stripping removes leading bullets (- * + •), decimal/letter list numbering with . or ), heading # marks, paired emphasis/backticks and a trailing ASCII/full-width colon. Spacing/punctuation equality additionally removes all Unicode whitespace and category-P punctuation, case sensitively.
Otherwise merged_or_split means all unit tokens occur in order across any ordered two answer lines (each contributes), or the tokens of that unit and a second complete reference unit occur consecutively in sequence in one line (intervening tokens allowed). Remaining classes use the closest-line Dice: reworded_high >=0.7, reworded_low >=0.3 and <0.7, absent <0.3. These classes do not assert that a new M21 normalization is allowed or that context bindings match.
Added-line priority is restyled_reference_unit (equal to any whole unit after either strip), offer_of_help (fixed English can-I-help/let-me-know/I-can-help or Korean offer phrases), question_to_user (terminal ?/？ or the fixed Korean question endings in code), commentary_with_state_label (any policy state-label substring), commentary_other. Phrase rules describe string patterns only; no LLM or semantic inference is used. Class keys and reason codes are closed constants.
Independent checks: every ask label appears as a verbatim substring; all unique policy state labels have identical literal substring counts; the complete counters of number lexemes `\d+(?:[-.:]\d+)*` match (including extra numbering); code-fenced=true only when all non-whitespace answer text is inside exactly one fence. Bytes are UTF-8; physical lines include blank lines and fences. No label/number values are exported.
Bounds: each reference/answer <=65536 bytes, <=512 physical lines, <=8192 normalized tokens; <=512 reference units; <=2000000 comparison-work units per turn. Dice/subsequence work charges token visits; normalization comparisons charge character lengths. Evidence files: metadata <=4194304 bytes, stream <=8388608, log <=1048576; stream/log <=4096 records; <=2 turns; <=256 requested rows/directories; <=64 matching candidate directories per row. Exceeding a bound returns analysis=unknown and a fixed *_limit, saved_file_bytes_limit or comparison_budget reason, with no line classes. The unchanged strict measure can separately return its existing reference/answer/search-budget unknown reasons. Loops and memory are bounded by these numbers.
Token counters are not interchangeable: public tokens are the client's per-turn result usage, aggregated over the initial request and tool-result continuations; cache-read+cache-creation there can exceed 6000 while the original first assistant request remains below it. run.py isolation reads only the first assistant message's usage input_tokens + cache_read_input_tokens + cache_creation_input_tokens in either mode. token_stop enforces <6000 only for isolated; installed records first_request_tokens without stopping. --conversation 1 (default) or 2 records independent samples in the row and saved measurement. --annotate-conversations <jsonl> adds legacy conversation=1 metadata, preserving previous bytes in a .before-conversation.jsonl file. A second conversation never replaces the first, and no unperformed turn gets a jsonl placeholder.
